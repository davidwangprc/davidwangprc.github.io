HTML元素在你的场景中各自承担的角色和背后的原理

Created on January 20, 2026

2026   ·   tech   jekyll

详细剖析 <figure> 和 <pre> 这两个HTML元素在你的场景中各自承担的角色和背后的原理。

1. <pre> 元素：内容保全的基石

<pre> 是“预格式化文本”（Preformatted Text）的缩写，其核心设计原理是“所见即所得”。

  • 核心作用：浏览器渲染 <pre> 标签内的文本时，会严格保留所有的空白字符（空格、制表符、换行符）。这与处理普通段落（<p>）的逻辑截然不同——普通段落中，连续的空白符会被合并成一个空格。
  • 技术实现：默认情况下，浏览器会为 <pre> 元素应用 white-space: pre; 这个CSS属性。这个属性值正是“保留所有空白，仅在换行符处换行”的指令。
  • 在您场景中的关键价值：
    1. 绕过渲染引擎：当你将代码直接放在 <pre> 标签内时，你实际上是在告诉Jekyll：“这部分内容我已经用原生HTML标记好了，不需要你进行Markdown到HTML的转换，更不需要调用语法高亮引擎（如Rouge）。” 这从根本上避免了因高亮引擎不支持 textile 或 liquid 语言而导致的渲染失败。
    2. 格式精确呈现：代码中的缩进、对齐、空行等结构会被原封不动地展示出来，这对于展示代码、命令行输出、ASCII图表等至关重要。

简单来说，<pre> 确保了内容的“形”不被改变。

2. <figure> 元素：语义关联的容器

<figure> 是一个语义化容器元素，其核心设计原理是“标记一个独立的内容单元，并允许为其提供说明”。

  • 核心作用：它用来包裹一块独立、自包含的内容（如图片、代码、图表、引文），并通过可选的 <figcaption> 子元素，将内容与其标题/说明在语义上明确地关联起来。
  • 技术实现：从功能上讲，<figure> 本身就像一个 <div>，但赋予了更强的语义。浏览器或辅助技术（如屏幕阅读器）可以识别这种关联，从而更好地理解页面结构。
  • 在您场景中的关键价值：
    1. 创建逻辑分组：它将 <pre>（代码块）和 <figcaption>（说明文字）捆绑成一个逻辑整体。这在文档结构上清晰地表明“这段代码和下面的标题是一体的”。
    2. 提升可访问性与SEO：这种语义化的标记有助于屏幕阅读器用户理解内容关系，同时向搜索引擎清晰地传达了内容的结构。
    3. 提供样式钩子：它为你提供了一个完美的、语义正确的“包装盒”，让你可以方便地为整个代码块单元（包括代码和说明）应用统一的CSS样式，比如添加边框、背景或外边距，而无需使用无语义的 <div>。

简单来说，<figure> 确保了内容与说明的“关系”被清晰地定义。

3. 二者协作的工作原理总结

你可以把这个组合理解为一个 “内容-说明”模块的标准化构建方式：

<figure> (语义容器：声明“这里是一个独立内容单元”)
    ├── <pre> (内容本体：确保内部文本格式被绝对保留，避开外部处理流程)
    └── <figcaption> (关联说明：描述该内容单元)

原理流程：

  1. 内容输入：你将原始代码文本直接放入 <pre> 标签内。
  2. 构建阶段：Jekyll 在处理 Liquid 模板时，会解析页面，但遇到 <pre> 标签时，会将其视为已完成的HTML，跳过内部的 Markdown 和 Liquid 解析。
  3. 输出与渲染：生成的静态 HTML 文件中包含完整的 <figure> 结构。用户的浏览器接收到后：
    • 根据 white-space: pre; 的规则渲染 <pre> 内的文本，完美保留格式。
    • 将 <figure> 及其内部的所有元素作为一个整体进行布局和样式渲染。
    • 通过语义理解 <figcaption> 是 <pre> 的说明。

因此，这个组合的成功，源于它巧妙地利用HTML标准本身的特性（<pre>的格式保留、<figure>的语义关联），在Jekyll的构建流水线中开辟了一条“绿色通道”，从而达到了精确控制最终渲染输出的目的。

Jekyll 构建阶段 (关键防御)

% raw % 和 % endraw % 是 Liquid 模板语言自身的“逃逸”指令。 当 Jekyll 处理你的 .md 或 .liquid 文件时，它会执行文件中的 Liquid 代码。但遇到 % raw %% endraw % 时，它会将这对标签及其包裹的所有内容视为纯文本，不进行任何 Liquid 解析或变量替换。 结果：HTML元素在你的场景中各自承担的角色和背后的原理 等语法被原封不动地写入最终生成的静态 HTML 文件，而不是被替换成实际标题值。

浏览器渲染阶段 (格式控制)

生成的静态 HTML 文件中，<pre> 标签内的文本已经是“安全”的纯文本。 浏览器解析到 <pre> 标签时，会默认应用 white-space: pre; 样式，严格保留所有空格、缩进和换行。 你添加的 style=”font-family: monospace; …” 进一步确保了代码以等宽字体美观显示，并具备背景、滚动等增强特性。
